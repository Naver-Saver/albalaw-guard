# 알바생 노동권 지킴이 프론트엔드

팀 저장소의 React + TypeScript + Vite 프로젝트입니다. 이 폴더를 이후 프론트엔드 작업 기준으로 사용합니다.

## 계약서 API 연결

질문 메뉴는 `POST /api/ask/text`로 2~300자 질문을 전송하고 실제 FAQ/Studio 답변과 근거를 표시합니다. 요청 중 취소·실패 재시도를 지원합니다. 질문 답변은 한국어이며 음성 질문과 TTS는 아직 연결하지 않았습니다. 화면을 나가면 질문 요청을 취소하고 화면 내 대화 기록을 해제합니다.

실제 결과의 설명·확인 항목·상담 안내는 업로드 단계에서 선택한 영어·베트남어·중국어로 `/api/translate`를 통해 번역합니다. 계산 데이터·고시·출처 제목과 원문은 그대로 유지합니다. 번역 중/실패 시 한국어 원문을 표시하며 실패 재시도와 원문 전환을 지원합니다. 메뉴·샘플 화면 전체의 다국어화는 포함하지 않습니다.

실제 계약서를 선택하고 개인정보 안내에 동의한 뒤 추출 버튼을 누르면 `POST /api/contracts/ocr`로 파일을 전송합니다. 추출값을 원본과 비교해 확인한 다음 `POST /api/contracts/review`로 점검합니다. 서버 계산값·항목·설명·근거를 표시하며 실패 시 오류와 재시도를 제공합니다. 샘플 문서 체험은 서버 요청 없이 기존 예시 화면을 사용합니다.

이 연결에는 실행 중인 백엔드와 백엔드의 OCR·Studio 설정이 필요합니다. 급여명세서 전용 점검은 준비 안내로 차단하고 번역은 아직 연결하지 않았습니다. 실제 유료 호출과 브라우저 검증은 PR에서 별도 확인합니다. 아래 퍼블리싱 단계의 샘플 설명보다 이 절의 실제 계약서 동작을 우선합니다.

## 실행

Node.js 22.12 이상을 사용합니다. 저장소 루트에서:

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

터미널에 표시된 개발 서버 주소를 엽니다(기본 `http://localhost:5173`). Windows PowerShell에서 `npm.ps1` 실행 정책 오류를 피하려면 위처럼 `npm.cmd`를 사용하면 됩니다. macOS/Linux에서는 `npm`을 사용합니다.

백엔드는 별도 터미널에서 루트 README의 방법으로 실행합니다. Vite가 `/api` 요청을 `http://localhost:8000`으로 전달합니다. 현재 공통 UI 미리보기는 API를 호출하지 않아 백엔드 없이도 확인할 수 있습니다.

```powershell
npm.cmd run lint
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

`build`는 TypeScript 검사 후 `dist/`에 배포 파일을 생성합니다. 현재 Vite 설정에서는 `preview`도 `/api` 프록시를 사용하므로 API 확인 시 백엔드를 함께 실행합니다. Docker·Nginx를 포함한 통합 확인은 저장소 루트의 `docker compose up --build`를 사용합니다.

## 현재 파일과 기준

| 경로 | 역할 |
| --- | --- |
| `src/main.tsx` | React 진입점과 전역 스타일 로드 |
| `src/App.tsx` | 작업 레이아웃과 공통 UI 미리보기 연결 |
| `src/components/common/` | 버튼·폼·카드·배지·화면 상태 공통 요소 |
| `src/components/layout/` | 헤더·사이드바·모바일 메뉴 |
| `src/pages/CommonUiPreview.tsx` | 공통 요소의 상태와 입력 동작을 확인하는 예시 화면 |
| `src/pages/DocumentUploadPage.tsx` | 언어·문서 종류·파일 선택·미리보기·동의 화면 |
| `src/features/document-upload/` | 파일 검사·로컬 미리보기 URL·취소 가능한 처리 상태 체험 |
| `src/pages/DocumentReviewPage.tsx` | 원본 비교·추출 내용 편집·원본 확인 동의 |
| `src/features/document-review/` | 샘플 OCR·입력 검증·동의 무효화·API-04 입력 형태 변환 |
| `src/pages/CheckResultsPage.tsx` | 샘플 계산값·확인 항목·공식 참고 자료·상담 안내 |
| `src/features/check-results/` | 고정 결과 응답·표시 타입·공식 링크 검사 |
| `src/pages/RecordingsPage.tsx` | 녹음 파일 선택·동의·샘플 타임라인과 대본 |
| `src/features/recordings/` | 녹음 파일 확장자·크기 검사 |
| `src/api.ts` | 백엔드 호출 코드 |
| `src/styles/tokens.css` | 공통 색상·폰트·모서리 변수 |
| `src/styles/global.css` | 로컬 폰트와 기본 스타일 |
| `src/assets/fonts/` | Noto Sans KR 가변 폰트 |
| `public/fonts/OFL.txt` | 배포 파일에도 포함되는 폰트 라이선스 |
| `../docs/design/` | 원본 와이어프레임과 해석 기준 |
| `../docs/spec/openapi.yaml` | 백엔드 요청·응답 명세 |

원본 SVG의 신청서 작성 문구는 화면 배치 참고용입니다. 실제 내용은 근로계약서·급여명세서 점검 기획에 맞춥니다.

Naver Cloud API 키는 프론트에 넣지 않습니다. 프론트는 팀 백엔드의 `/api`만 호출합니다. API 연결 시 `main`에 반영된 명세와 공통 응답 형식을 확인합니다.

## 화면 주소

- `/#/`: 서비스 소개 (처음 접속 시 기본 화면)
- `/#/guide`: 이용 안내 영상 전용 페이지. 영상이 제공되지 않으면 준비 상태와 글 안내를 표시합니다.
- `/#/workspace`: 언어·문서 종류·파일 선택 화면. 파일 선택·동의 후 체험 버튼은 실제 전송 없이 직접 입력 화면으로 연결됩니다. 파일 없이 샘플 문서 체험도 가능합니다.

`npm.cmd test`는 경로·소개/영상 렌더링, 파일 검증, 체험 취소, 편집 폼의 검증·확인 동의·API-04 입력 형태와 실제 파일/샘플 구분, 결과 예시·근거 없는 상태·공식 링크 검사를 확인합니다. 실제 브라우저 클릭 및 모바일 화면 검증을 대체하지 않습니다.

문서 파일은 메모리와 객체 URL에서만 다룹니다. 편집 흐름의 관련 메뉴 사이에서는 원본과 수정값을 유지하며, 새 문서 선택·서비스 소개 이동 시 참조를 해제합니다. 원본 컴포넌트가 닫힐 때 객체 URL은 해제합니다. PDF를 새 탭으로 열었다면 해당 탭은 직접 닫아 주세요. 현재 단계에서 PDF 페이지 수는 검사하지 않습니다.

샘플 OCR 값은 샘플 문서에서만 표시합니다. 실제 업로드 원본에는 임의 OCR 값을 채우지 않으며 직접 입력으로 시작합니다. 확인 후 결과 화면은 입력값과 연결되지 않은 고정 샘플 응답입니다. 입력값은 별도 영역에서 확인하며 실제 OCR·점검 요청이나 프론트 금액 계산은 하지 않습니다.

결과 화면의 ‘다른 예시 상태 살펴보기’에서 기본·설명 없음·근거 없음·처리 중·오류를 전환할 수 있습니다. 근거가 없으면 설명도 숨깁니다. 공식 자료는 고용노동부 보도자료와 국가법령정보센터의 참고 링크이며, 업로드 문서에 맞춰 검색한 백문백답 결과가 아닙니다. 질문 버튼은 준비 화면으로 연결되고 결과로 돌아갈 수 있습니다.

녹음 메뉴에서는 파일 선택·동의와 화자 이름 변경, 분류 필터, 샘플 대본을 체험합니다. 파일을 전송하거나 분석하지 않으며 결과는 선택한 파일과 관계없는 고정 예시입니다. 파일 길이는 검사하지 않습니다.
