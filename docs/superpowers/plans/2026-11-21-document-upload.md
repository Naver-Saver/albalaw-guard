# 문서 업로드 화면 구현 계획

사용자가 승인한 4번 퍼블리싱. 기준: 원본 SVG 01, FR-01, FS-01 단계 1, BR-01, NFR-01·02·03·06. 실제 OCR API와 추출 내용 수정은 9번·5번 작업으로 분리한다.

## 범위

- 언어 4종과 계약서·급여명세서 선택
- 로컬 파일 선택·드래그 앤 드롭·지원 기기의 카메라 입력
- 파일 1개, JPG/JPEG/PNG/PDF, 최대 10MiB. 빈 파일과 확장자/MIME 불일치를 거부한다. MIME이 제공되지 않는 기기는 확장자로 검사한다.
- 이미지 미리보기·PDF 새 탭 보기·선택 파일 삭제/교체. 객체 URL을 교체·삭제·화면 종료 시 해제한다.
- 동의·파일 없으면 체험 버튼 비활성. 파일 교체 시 동의 초기화. 처리 중 상태는 서버 전송이 없는 시뮬레이션이다.
- 파일, 언어, 문서 종류, 동의 변경과 화면 종료 시 진행 중 체험을 취소한다.
- 다른 작업 메뉴는 준비 상태만 보여준다. 현재 선택 파일은 화면 이동 시 해제된다.

## 결정과 한계

- PR #35가 미머지 상태이므로 3번 브랜치를 기반으로 한 누적 PR로 제출한다. 3번 머지 후 base를 main으로 변경할 수 있다.
- 요청에 따라 CI 결과를 기다리지 않는다.
- 테스트용 Vite 서버에서 HMR뿐 아니라 별도 WebSocket을 꺼 병렬 실행의 포트 충돌을 해결했다.
- PDF 페이지 수와 파일 본문의 유효성 검사는 아직 하지 않는다. 업로드 1파일 제한과 PDF 1페이지 준비 안내를 제공하며, 실제 수신 검사는 백엔드 연결 시 적용한다.
- 새 화면의 실제 브라우저·카메라·드롭·모바일 확인은 미완료다. 자동 렌더링·파일 메타데이터 테스트가 이를 대신하지 않는다.
