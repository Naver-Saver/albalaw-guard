# PRD — 알바생 노동권 지킴이 (albalaw-guard)

> 상태: **초안 v0.1** · 네이버 클라우드 소버린 AI 리터러시 과정 팀 프로젝트 (기간 2주)
> 이 문서는 "왜·무엇을·어디까지"를 정합니다. "어떻게"는 [명세 문서(SDD)](spec/README.md)에 있습니다.
> 이 문서는 팀이 함께 고치는 문서입니다. 확정되지 않은 항목은 `[미정]`으로 표시하고, 결정되면 "결정 기록"에 남깁니다.

## 1. 한 줄 요약

근로계약서·급여명세서 사진과 사장님과의 대화 녹음을 정리하고, **법제처 생활법령 백문백답(근로자 분야)** 을 근거로 "확인이 필요한 부분"을 쉬운 말로 알려주는 웹 서비스.

## 2. 문제 정의

| 문제 | 근거/상황 |
| --- | --- |
| 알바생은 계약서·명세서를 받아도 최저임금·주휴수당이 맞게 들어갔는지 스스로 확인하기 어렵다 | 계산식(주휴시간 = 주 소정근로시간/40×8)과 매년 바뀌는 최저임금을 모름 |
| 임금·근무시간 관련 구두 약속은 증거로 남기 어렵다 | 녹음은 있어도 길고 정리가 안 됨 |
| 법령 정보는 어렵고 흩어져 있다 | 공식 Q&A가 있어도 찾기·읽기 어려움 |
| 외국인 알바생은 언어 장벽이 추가된다 | 한국어 계약서·안내 이해 곤란 |

## 3. 대상 사용자

- **P1. 대학생 알바생** — 첫 알바, 계약서 내용을 잘 모름. 모바일 웹 사용.
- **P2. 외국인 알바생** — 한국어 문서 이해가 어려움. 번역이 필요.
- (발표 청중) 평가자 — "여러 NCP AI 서비스를 적절하게 엮었는가"를 봄.

## 4. 목표 / 비목표

**목표**
1. 사진 1장으로 시급·근무시간을 추출하고, **코드로 계산한** 최저임금·주휴수당 점검 결과를 보여준다.
2. 모든 설명에 **원문 출처(백문백답 문항)** 를 함께 표시한다.
3. NCP AI 서비스 8개(OCR, Papago, Studio, Chatbot, CSR, Speech, Voice, Dubbing)를 **역할이 겹치지 않게** 사용한다.
4. 2주 안에 시연 가능한 하나의 흐름(업로드 → 점검 → 설명 → 음성 안내)을 완성한다.

**비목표 (이번 프로젝트에서 안 함)**
- 법률 자문, 위법 여부 "판정" — 안내·근거 제시까지만 한다.
- 회원가입/로그인 — `[미정]` 시간이 남으면 익명 세션 ID만.
- 계약서·녹음 원본 장기 보관 — 처리 후 삭제가 기본.
- 네이티브 앱 — 반응형 웹만.
- Maps — B안에서는 사용하지 않음.

## 5. 범위와 우선순위

| 우선순위 | 기능 | 설명 |
| --- | --- | --- |
| **P0** | F1. 계약서·급여명세서 점검 | 핵심 시연 흐름. 이것만 되어도 발표 가능 |
| **P0** | F5. 근거 원문 데이터 준비 | 백문백답 근로자 분야 수집·캐싱 (F1·F3의 근거) |
| **P1** | F3. 빠른 음성 질문 | CSR → Chatbot/Studio 라우팅 → Voice |
| **P1** | F2. 대화 기록 정리 | CLOVA Speech 장문 + 화자 분리 → 타임라인 |
| **P2** | F4. 교육 영상 | CLOVA Dubbing으로 제작한 영상 게시 (콘텐츠) |
| **P2** | F6. 다국어 표시 | Papago로 결과 번역 (언어 선택 토글) |

> 진행 원칙: **P0 흐름을 첫 주 안에 끝까지 한 번 관통**시킨 뒤 품질을 올리고, 남는 시간에 P1 → P2 순으로 확장.

## 6. 기능 개요

> 상세 동작·업무 규칙·완료 조건은 **[기능 명세](spec/02-functional-spec.md)** 가 기준입니다. 여기에는 요약만 둡니다.

| 기능 | 흐름 요약 | 명세 |
| --- | --- | --- |

| F5. 근거 원문 데이터 | 백문백답 근로자 분야 수집·캐싱·검색 | FS-06 |

## 7. 서비스별 역할 매핑

| NCP 서비스 | 쓰이는 기능 | 역할 |

## 8. 아키텍처

```
[브라우저 (React/Vite)]
        │  HTTPS
        ▼
[NCP Server · Docker Compose]
   ├─ frontend: Nginx (정적 파일 + /api 프록시)
   └─ backend : FastAPI
          ├─ CLOVA OCR / Speech / Studio / Chatbot
          ├─ Papago / CSR / Voice (AI·NAVER API)
          ├─ Object Storage (업로드 임시 + 법령 원문 JSON)
          └─ data.go.kr (백문백답·생활법령)

GitHub Actions ─ CI: lint·test·build / CD: NCR push → SSH 배포
```

## 11. 데이터·개인정보 원칙

- 계약서·명세서·녹음 **원본은 처리 후 즉시 삭제**, 이름·주소·계좌 등 사용자 데이터는 어디에도 저장하지 않는다.
- 녹음 업로드 전 "대화 당사자 녹음 관련 주의" 안내와 동의 체크.
- API 키는 `backend/.env`(git 미추적)와 GitHub Secrets에만 둔다. 프론트엔드에서 외부 API 직접 호출 금지.
- 모든 AI 답변에 출처 표시 + "법률 자문 아님" 고지.

| 서비스마다 다른 인증 방식 | `core/config.py`에 키 일원화, 서비스별 클라이언트 모듈 |
| 키 유출 | `.gitignore`, PR 체크리스트, 프론트에서 직접 호출 금지 |

## 16. 성공 기준 (발표 기준)

- 시연 시나리오 3개(계약서 점검 / 음성 질문 / 녹음 정리)가 끊김 없이 동작.
- 사용한 NCP AI 서비스 8개 각각의 역할을 한 장으로 설명 가능.
- 모든 답변에 근거 출처가 표시됨.
